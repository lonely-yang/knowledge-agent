  二、容器化（现在 compose 是坏的）

  - 根 Dockerfile 是 ES+IK 的，但 compose 里 aiagent-end: build: . 拿它构建应用镜像——需要给 FastAPI 应用单独写 Dockerfile（python 基础镜像 + requirements + uvicorn）
  - compose 里 elasticsearch: build: ./elasticsearch 但该目录不存在
  - mysql 服务和 DB_HOST=mysql 是别的项目残留，本应用用 PG，应删

  三、安全（必须）

  - 全项目同一个弱密码 lyp82nlfxxlE（PG/Mongo/Redis/RabbitMQ/compose healthcheck 里都有）→ 生产全部换强密码
  - API 无任何鉴权：能访问 8000 端口就能 publish/delete → 加登录认证或在网关层做
  - 管理工具不要暴露公网：pgAdmin(5050)、RedisInsight(5540)、Mongo Express(8081)、Kibana(5601)、RabbitMQ 管理台(15672)、MinIO/RustFS console、Neo4j Browser(7474) → 生产删掉或仅内网访问
  - HTTPS：nginx 做 TLS 终结，后端 http 即可

  四、基础设施与运维

  - 服务器内存：ES + Milvus + Neo4j + PG + Mongo + RabbitMQ + etcd + MinIO 全家桶，最低 16G 起；ES/Neo4j 的堆配置要按生产调（物理内存 50%，ES_JAVA_OPTS 现在才 512m）
  - ES 单节点 → 生产至少备份策略 + 考虑集群
  - 数据备份：所有 volume 定时备份；或决定线上重新入库（本地 volumes 数据导不导线上，需要你定）
  - 前端（Vite 项目）单独构建部署：build 后 nginx 静态托管 + /api 反代
  - 监控告警：容器健康、磁盘、DLQ 队列积压、日志收集
